# IronLaw · 把工程纪律变成机器

一套把「靠自觉」变成「靠机器」的工程纪律系统。核心理念只有一句：

> **能被机器检查的，就不要靠人记得。**

## 一句话路由

| 用户想干什么 | 加载 |
|---|---|
| 修 bug、加功能、从根源修、复盘、撞文件 | `ironlaw-change` |
| 加门禁、补守卫、门禁假红假绿、CI 卡住 | `ironlaw-gate` |
| 写变更档案、影响链、提交信息 | `ironlaw-record` |
| 发版、部署、出包、线上版本对不上 | `ironlaw-ship` |
| 开新项目、初始化仓库、铺规范 | `ironlaw-bootstrap` |
| 不确定 / 要全流程 | 先读完本文，再按下方「全流程」逐步加载 |

## 全流程（五段，按顺序）

```
① bootstrap          一次性：把设施铺好（新项目才需要）
        ↓
② change             每次改动：开工六问 → 根因 → 影响链 → 修复
        ↓
③ gate               把这次的判据钉成机器可查的守卫
        ↓
④ record             七段档案 + §2.5 机器断言 + 三段式提交信息
        ↓
⑤ ship               推送 → 出包 → 部署 → 线上真值核验 → 台账
```

不是每次都五段全跑。**判断标准**：

- 改一行文案 → 只跑 ②，`record` 可省（若不涉产品代码）
- 改产品代码 → ②③④⑤
- 只加门禁 → ②③④（⑤看是否要上线）
- 新项目 → ①，然后等第一次真实改动再走 ②

## 四条铁律（违反任何一条，整套失效）

1. **必填必须 fail-closed** —— 缺文件、缺章节、空数据分支必须判红。放行等于条款不存在。
2. **新守卫必须带反向探针** —— 去掉保护必须转红，且能逐字节复原。不验证「改坏会红」的守卫，等于没有守卫。
3. **跨脚本口径放单一真源** —— 同一个判定只能有一份实现。禁止两份正则互相掩护。
4. **影响链用机器算的覆盖率逐键闭环** —— 漏掉的键必须点名，不许用「都检查过了」结案。

细节与反例见 `ironlaw-change/references/iron-laws.md`。

## 四个可直接跑的工具

| 工具 | 位置 | 干什么 |
|---|---|---|
| `reverse-probe.mjs` | `ironlaw-gate/scripts/` | 反向变异：改坏 → 必须转红 → md5 复原 |
| `verify-record.mjs` | `ironlaw-record/scripts/` | 执行档案 §2.5 断言表，逐条报告 |
| `impact-scope.mjs` | `ironlaw-record/scripts/` | diff → 范围键 → 逐键对照 §2.5/§2.6，漏键点名（铁律四的机器侧） |
| `ship-truth.mjs` | `ironlaw-ship/scripts/` | 四方真值核验：本地 / 远端 / 线上 / 分发 |

都在技能目录内，用 `node <path>` 直接跑，无第三方依赖。`ironlaw-bootstrap` 脚手架还会把 `verify-record` / `safe-push.sh` / `bump-version.mjs` 铺进项目仓库。

## 这套东西不做什么

- 不替你决定产品怎么做——它只管「改动是否可信」。
- 不追求门禁数量——跑不完的门禁等于不存在。
- 不假装成功——「push 成功」≠「部署了」，「脚本说 OK」≠「线上是新的」。

## 最短上手路径

新项目：

```bash
node <ironlaw-bootstrap>/scripts/init-project.mjs /path/to/repo
```

老项目只补纪律：读 `ironlaw-change`，从「开工六问」开始，第一次改动就把 ②③④ 走一遍。

任何时候不确定该用哪个，回到本文的「一句话路由」。
