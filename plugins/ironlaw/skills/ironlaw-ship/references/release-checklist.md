# 上线清单

## 发版前

- [ ] 远端已对账（`git ls-remote`），没有别人正在发布
- [ ] 工作区干净，或改动已全部提交
- [ ] 版本号三处一致（根/前端/后端），且已 bump
- [ ] 变更档案七段齐全，`verify-record` 通过
- [ ] 提交信息三段齐全（根因/影响链/验证），行首匹配
- [ ] 全量门禁绿，日志末尾有独立哨兵（`EXIT=0`）
- [ ] 发版欠账为 0（或已解释欠了哪几版）

## 推送

- [ ] 用安全推送脚本，不带 `--force`
- [ ] 推送前先 merge（快进优先），不 rebase
- [ ] 退出码单独捕获（不经管道）
- [ ] `git ls-remote` 的 sha == 本地 HEAD
- [ ] 若合并了远端，**重跑全量门禁**

## 出包

- [ ] 构建产物可复现（同 commit 两次构建内容一致，或有明确的不确定性来源说明）
- [ ] 双核验：旧版本号能拉到新包（200 + manifest 指纹正确）；新版本号返回无更新（204）
- [ ] 包体积在合理区间（突增/突减都要解释）
- [ ] 指纹（sha256 / size）已记录

## 台账

- [ ] 最新版本 / 基线提交 / 产物指纹三处写入
- [ ] 台账版本 == `package.json` 版本
- [ ] 台账里出现"本次部署"的时间与执行人
- [ ] 有其它线同时在写台账时，按时间序**两边都保留**
- [ ] 台账提交已推送（否则下一个人看到的是旧台账）

## 部署

- [ ] 无陈旧锁；无并发部署进程
- [ ] 发布权已确立（若机制要求）
- [ ] 前置对账通过（工作区干净 / 本地 HEAD 在远端 / 台账一致）
- [ ] 前后端都部署（只部署一半 = 契约不匹配）
- [ ] 数据迁移先备份，且逆操作可用

## 部署后

- [ ] 版本接口返回 == 本地版本
- [ ] 入口 chunk 与本地构建产物一致
- [ ] 双向 grep：新增符号 >=1，删除文案 =0
- [ ] 页面级遍历全过（警告单独计数）
- [ ] 关键交互真机/真浏览器走一遍（写路径必须）
- [ ] 日志无异常堆栈
- [ ] 分发通道版本 == 本地版本

## 收尾

- [ ] 变更档案回填真实上线证据（不是"待部署"）
- [ ] 报告/README 里声明的版本号已更新
- [ ] 工作记忆记录本次新踩的坑
- [ ] 最终推送后，`ship-truth` 全绿

---

## 一条判据

> 如果现在换一个人接手，他只看这份台账和三个接口返回值，能不能判断"线上跑的就是这次提交"？

不能 → 少记了一样东西。
