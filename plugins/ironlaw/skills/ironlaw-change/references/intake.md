# 开工前：六问 · 真源定位 · 影响链清单

动手前把这三张表填完。填不完就说明还没准备好，不是"边做边想"。

---

## 一、开工六问

逐条写答案，写不出就继续查。

### 问 1 · 缺数据行为（排第一）

这条判据/这段代码，在下列六种情况下会怎样？

- 缺文件（配置/基线/台账不存在）
- 缺章节（文档少一段）
- 缺参数（`undefined` / 空字符串 / 0）
- 空数组（合法为空 vs 不应该为空）
- 超时（请求/进程/子任务）
- 异常（网络/权限/解析）

每种都要能回答"判红还是判绿"。**判绿的每一处，写一句为什么安全。** 写不出理由的，一律改判红。

### 问 2 · 根因位置

> 根因是 X，不是 Y。

一句话写不出来 = 还在猜，禁止动手。

### 问 3 · 影响链

用下面第二张表逐类 grep，把命中路径列成清单。

### 问 4 · 失败可见性

- 改坏了谁先发现？（用户 / 监控 / 门禁 / 没人）
- 多久能发现？（下次部署 / 下次使用 / 永远）
- 有没有断言能在**提交前**钉住？

"没人会发现"是必须消除的状态——至少补一条断言。

### 问 5 · 反向变异

> 把这次修复删掉，哪条断言会转红？

说不出具体断言名 = 这条修复没有被验证，只是"看起来对了"。

### 问 6 · 裁定归属

以下情况必须问用户，列 2~3 个选项 + 推荐项，一次问完：

- 命名（术语选词，尤其是跨行业通用词 vs 单一行业黑话）
- 口径（金额含税/不含税、时间本地/UTC、单位）
- 交互语义（删除是软删还是硬删、默认排序）
- 结构（菜单层级、页面归属、入口位置）

**工程师觉得更合理不构成批准。** 结构变更（导航/路由/默认落地页）必须先拿明确批准。

## 二、症状 → 真源映射表

| 症状 | 真源通常在这 | 不要改这 |
|---|---|---|
| 字段名/标签不一致 | 常量真源表、schema、DTO 白名单 | 各个组件里的显示文案 |
| 同一概念两种叫法 | 术语真源文件（唯一出口） | 逐个替换组件字符串 |
| 行为不一致（分页/过滤/删除） | 生成该行为的公共模式（列表页 fetch 约定、动作 hook） | 单个页面的特判 |
| 时有时无的 bug | 先复现，拿稳定路径 | 凭日志猜 |
| 数据对不上 | 写入路径代码（不是读取侧渲染） | dev 库采样结论 |
| 权限越权 | 作用域合并逻辑（`AND: [scope, cond]` 而不是覆盖 `OR`） | 单个 controller |
| 日期差 8 小时 | 本地时间被拼成 UTC 字符串 | 显示层格式 |
| 数量/金额偏差 | 单位与币种口径（对客 vs 内部） | 展示格式化 |
| 导出的和页面不一致 | 导出模板 / 打印样式 | 页面组件 |
| 移动端和网页端不一致 | 两端共享的规则包 | 各端分别打补丁 |
| 门禁红了但本地能过 | 环境差异（shell/盘符/cwd/依赖） | 产品代码 |
| 同款失败反复出现 | 机制允许跳过 | 要求自己"更仔细" |

### 一条实战判据

> 用户报的现象是**症状**，不是真源。往上追一层再动手。
>
> 例：用户说"订单列表列顺序反了" → 真源不是"排序函数写错"，而是"入口列序定义与人阅读顺序相反"。改排序函数只修了这一次，改定义修了全部。

## 三、影响链六类检查表

改任何"被多处引用"的符号（字段名/标签/文案/公共函数/路由/枚举值），逐类跑一遍。

### 1. 渲染点

```
grep -rn "<旧符号>" --include=*.vue --include=*.tsx --include=*.ts src/
```

- 组件模板
- 列表列定义
- 详情页配置（通常是一个 config 对象数组）
- 页签 / 抽屉 / 弹窗

### 2. 契约点

- API 请求/响应类型
- DTO 白名单（`pickWritable` 一类）
- Controller 参数
- 前后端共享类型包（`packages/shared` 一类）
- 校验 schema

### 3. 产物点

- PDF 模板
- Excel/CSV 导出列
- 打印样式
- 邮件模板
- 消息通知文案

> 这一列最常被漏，因为"系统里看着对了"，但客户拿到的是导出的单证。

### 4. 测试点

```
grep -rn "<旧符号>\|<旧行为关键词>" --include=*.spec.ts --include=*.test.ts --include=*.mjs test/ scripts/e2e/
```

- 单测断言
- e2e 场景断言
- 基线快照 JSON

**断言旧行为的测试必须在同一提交更新**，否则要么红，要么更糟：绿着断言旧语义。

### 5. 文档点

- 台账（STATUS / RELEASE 一类）
- 设计文档
- 变更档案
- 代码注释里的旧名
- 用户手册 / 帮助文案

### 6. 联动点

- `watch` / 派生状态
- 后端 `ensure*` 同步逻辑（改主对象归属要触发子记录同步）
- 缓存失效
- 权限派生
- 通知/事件订阅

> 改了主对象的一个字段，联动逻辑没跟上 = 数据表里看着对，关联表里是旧的。

## 四、动手前的最后一道门

三句话都能说出来，才允许改代码：

1. 根因是 ___，不是 ___。
2. 影响链共 ___ 处，清单在 ___。
3. 改坏了 ___ 会转红。

说不出来 → 回到问 1。
