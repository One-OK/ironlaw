# 门禁静默失效的九种形态

门禁最坏的结局不是"红"，是"绿着但没守"。以下九种按发现难度排序，越靠后越难自查。

---

## 1 · 空数据放行

```js
if (!records.length) { console.log('OK'); return 0; }
```

"什么都没做"和"做对了"得到同一个结论。

**修**：区分"合法为空"与"不应该为空"。前者写理由注释，后者返回 1。

---

## 2 · 跳过了仍计通过

```js
if (真实资源被占用) { log('跳过'); pass++; }   // ← 最阴的一类
```

本机恰好有真实部署锁、恰好端口被占、恰好缺凭据 → 跳过 → 报告全绿。换台机器就红。

**修**：探针必须用隔离资源（唯一路径/端口/临时库），永不因本机状态跳过。若必须跳过，单独计数、单独展示，不并入通过数。

---

## 3 · 超时被当成"通过"

```js
const r = spawnSync(cmd, { timeout: 60000 });
if (r.status === 0) pass();      // status 为 null 时既不 pass 也不 fail
```

`status === null` 是"进程被杀"，不是"通过"，也不是"失败"。有些实现把它归入"未通过"→ 假红；归入"无错误"→ 假绿。

**修**：显式分支 `if (r.status === null) → 设施超时（退出 2）`，并把超时预算与真实耗时对齐（内层 × 并发数 < 外层）。

---

## 4 · 失败原因被正则吞掉

```js
const bad = out.split('\n').filter(l => /❌|FAIL/.test(l));
```

聚合器输出的是：

```
❌ 部署登记漂移
↳ 退出码 1
```

`↳ 退出码 1` 被吞 → 只知道红了，不知道为什么 → 人去猜 → 猜错 → 修错地方。

**修**：失败行正则必须含 `^\s*↳`、`! S\d+`、`⚠ 跳过`。且这段正则只能有一份。

---

## 5 · 判据散落成两份

主脚本一份、调试副本一份、CI 一份。它们逐渐错位——而**日常跑的那份才是真正生效的那份**。

**修**：抽到 `scripts/lib/`，各处只 import。加"双副本漂移守卫"比对两份的步骤名/顺序/共享件引用。

---

## 6 · 生成器不产出必填段

骨架生成器不生成 §2.5，人看不到这一节 → 没人写 → 检查器对"缺 §2.5"判 OK → 12 份档案 7 份缺。

三方同时失效。**这一类的特征是：每一方单看都"合理"**。

**修**：生成器必产该段（哪怕只有标题 + TODO）；检查器对缺失判红；两者共用同一份"必填段清单"。

---

## 7 · 门禁本身是死代码

脚本写好了，本地能跑，但没挂进任何聚合器/pre-commit/pre-push。**没人跑它**。

典型自欺："我加了个检查"，实际从写下那天起运行 0 次。

**修**：注册守卫统计 `check-*.mjs` 数量 vs 聚合器注册数，差值 > 0 判红并点名。

---

## 8 · 判据钉的是数据快照

```js
expect(count).toBe(0);   // 假设夹具里没有相关记录
```

有人录了一笔业务数据 → 断言红 → 你去"修产品" → 产品本来是对的。

**修**：钉规则不钉快照（实时读接口比对）；依赖数据前提的断言显式声明为 soft。

---

## 9 · 门禁自身有 TOCTOU / 竞态

先判断"文件存在"，再读；中间被别人删了 → 崩。或先读 A 再读 B，两读之间 B 变了 → 判据基于不一致的快照。

**修**：读一次、用内存中的那份；对"必须成对出现"的输入做同批次读取并在判据里标注版本/时间戳。

---

## 自查：一次"全绿"意味着什么

| 问 | 若答"否" |
|---|---|
| 这条门禁今天运行过吗？ | 形态 7 |
| 它今天扫到了非空数据吗？ | 形态 1 |
| 它今天没有跳过任何一项吗？ | 形态 2 |
| 它有把"原因行"打出来吗？ | 形态 4 |
| 它和调试副本用的是同一份判据吗？ | 形态 5 |
| 去掉它守的代码，它会红吗？ | 形态 1/3/6 |

六问全"是"，绿色才有意义。
