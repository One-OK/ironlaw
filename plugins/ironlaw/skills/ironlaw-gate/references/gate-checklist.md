# 门禁验收清单

写完/改完一个守卫，逐条勾。任一未勾 = 不许合入。

## A. 判据

- [ ] 判据只有**一处实现**（`evaluate()` 或等价函数），正式扫描与 `--selftest` 都调它
- [ ] 规则表是数据（数组/对象），不是散落在 if-else 里
- [ ] 每条规则有 `id` 与 `desc`，输出时报 `id`
- [ ] 正则带 `g`，且计数用 `exec` 循环或 `matchAll`，不用 `String.match` 求长度
- [ ] 期望值只有三种：`absent`（=0）、`present`（>=N）、精确 `=N`；没有第四种

## B. 缺数据（fail-closed）

- [ ] 范围目录不存在 → 退出 1，报路径
- [ ] 目标文件为空 → 不崩，且按规则判定（不是默认通过）
- [ ] 空数组 → 判红，或判绿**且代码注释写了理由**
- [ ] 超时 → 退出 2 并标注"设施超时"，不混入判据失败
- [ ] 异常 → 至少输出一行原因，无 `catch {}` 空块
- [ ] 参数缺失 → 报错退出 2，不用默认值悄悄兜住

## C. 自证

- [ ] 正例：干净样本必须放行
- [ ] 反例：注入一处违规必须判红
- [ ] 反例：去掉必需模式必须判红
- [ ] **反向探针**：把判据改坏（永远 true / 正则改成永不命中）→ 上面那条反例必须**不再红**，证明红确实来自该判据
- [ ] 空数据探针：空文件集不得假绿
- [ ] 自证条数写在输出里（`[selftest] 5/5`），少于 3 条视为不合格

## D. 输出

- [ ] 失败时打印：规则 id + 文件相对路径 + 命中数 + 一句为什么
- [ ] 成功时打印：扫描文件数 + 规则数
- [ ] 支持 `--json`（机器可读，含 counts 与 violations）
- [ ] 没有 emoji 之外的装饰性输出干扰解析（emoji 仅用于快速视觉定位，不承载语义）

## E. 退出码

- [ ] 0 = 通过
- [ ] 1 = 判据红
- [ ] 2 = 配置/设施错误
- [ ] 「跳过」不增加通过计数；跳过的项在输出里单独一行

## F. 注册与成本

- [ ] 已加入聚合器的步骤表，且步骤名描述"守什么"而不是"脚本名"
- [ ] 已加入注册守卫的白名单/统计
- [ ] 单次运行 < 5s（超了先想能不能只扫 diff 范围）
- [ ] 有 `timeoutMs`，且超时值与内层实际耗时有 ≥2 倍余量
- [ ] 在 CI 与本地跑结论一致（shell 差异已验证）

## G. 反向变异记录

- [ ] 至少一组变异，用 `reverse-probe.mjs` 跑过
- [ ] 输出贴在 PR/变更档案里，含"变异 → 转红 → 复原 md5 一致"
- [ ] 变异前基线必须先通过（否则变异后的红没有意义）

## 一行判据

> 这个守卫，**删掉它所守的那段代码**，它会红吗？
> 不会 → 它守的不是那段代码。
