# 门禁工程：让纪律物理生效

## 这个技能解决什么

规范写在文档里管不住人，只有"推不出去"才管得住。但**门禁自己也会失效**，而且失效时是静默的——它给你一个绿色的 ✓，你读到 ✓ 就以为没问题。

真实现象：生成器不产出某章节 → 检查器对"缺该章节"判 OK → 12 份档案 7 份缺该章节 → 其中一份跨四个包、删了 7 个端点 → 推送门禁全绿。三处同时失效，**互相掩护**。

所以写门禁的标准比写业务代码更高：**它不是"能跑"，是"改坏了必须红、没做必须红、跳过了不许算通过"。**

## 门禁七要素（缺一条就是假门禁）

| # | 要素 | 不满足的后果 |
|---|---|---|
| 1 | **判据单一真源**：正式扫描与自证共用同一个 `evaluate()` | 自证绿、生产红，或反过来 |
| 2 | **缺数据 fail-closed**：缺目录/缺章节/空数组/超时都判红 | 建仓第一天就绿，等于没有 |
| 3 | **反向探针**：去掉保护必须转红，快照还原法验证 | 分不清"实现了"和"没实现" |
| 4 | **失败可归因**：输出点名「哪条规则 + 哪个文件 + 为什么」 | 红灯无法定位，人开始忽略红灯 |
| 5 | **退出码有语义**：0 通过 / 1 判据红 / 2 设施错误 | 设施问题被当产品缺陷修 |
| 6 | **注册进聚合器**：挂到 `check-all` / `check-guards` | 本地能跑但没人跑 = 死代码 |
| 7 | **成本可接受**：单条 < 5s，超时预算明确 | 一次全量 20 分钟，人就不跑了 |

## 一、先写判据，再写扫描

80% 的门禁是同一个形状：**规则表 + 遍历 + 计数**。

```js
const RULES = [
  { id, desc, scope, ext, pattern: /.../g, expect: 'absent' },              // 零残留
  { id, desc, scope, ext, pattern: /.../g, expect: 'present', min: 2 },     // 必须存在
];
```

复制 `assets/guard-skeleton.mjs` 到 `scripts/check-<topic>.mjs`，只改 `RULES`。骨架内建：单一真源 `evaluate()`、缺目录 fail-closed、`--selftest` 五条探针（含反向探针）、`--json`。

改完后必须跑：

```bash
node scripts/check-<topic>.mjs --selftest   # 必须全通过
node scripts/check-<topic>.mjs              # 正式扫描
```

`pattern` 必须带 `g`（否则 `lastIndex` 会让计数漏）；`scope` 目录必须存在（不存在就判红，不跳过）。

## 二、缺数据矩阵（逐格想一遍）

| 空形态 | 错误写法 | 正确写法 |
|---|---|---|
| 目录不存在 | `if (!existsSync(d)) return 0` | `throw` → 退出 1 |
| 章节缺失 | `if (!sec) continue` | 触及产品源码且缺该章节 → 退出 1 |
| 空数组 | `if (!rows.length) { log('OK'); return 0 }` | 若"必然应有"→ 1；若"合法为空"→ 0 **并写理由** |
| 参数缺失 | `opts?.x ?? 'default'` | 默认值只许一处；第二处默认值 = 第二套口径 |
| 超时 | `status === 0`（null 被当成功） | `status === null` → 显式报"设施超时"，退出 2 |
| 异常 | `catch {}` | 至少输出一行原因，禁止静默吞 |

### 判据自检一句话

> 这条门禁，如果今天仓库里什么都还没做，它会不会也判绿？

会 → 它守的是"没崩"，不是"做了"。

## 三、反向探针（必须有）

只有正向探针（喂正确数据 → 通过）的门禁等于没有门禁。

用 `scripts/reverse-probe.mjs`（本技能自带，已验证三条路径）：

```json
{
  "file": "src/guard-target.ts",
  "cmd": "node scripts/check-target.mjs",
  "cases": [
    { "label": "把 fail-closed 改成 fail-open", "find": "if (!rows.length) return 1;", "replace": "if (!rows.length) return 0;" },
    { "label": "判据改成永远通过", "find": "ok = evaluate(rows);", "replace": "ok = true;" }
  ]
}
```

```bash
node scripts/reverse-probe.mjs --config probe.json
```

它会：基线必须先过 → 快照 → 精确变异（命中数必须等于期望）→ 跑守卫 **必须非 0** → 逐字节复原 → md5 比对。任一案例"变异后仍绿"→ 退出 1 并点名。

### 禁止的反模式

| 反模式 | 为什么坏 |
|---|---|
| 用反向字符串替换复原 | 漏空白/行尾/编码差异，留下污染 |
| 变异用全局替换 | 可能命中多处，改到了别的判据 |
| 只测"应该失败"不测"应该通过" | 门禁可能永远红，同样没用 |
| 变异后仍然绿还当通过 | 这就是"假守护"，本技能要防的核心 |

## 四、判据单一真源

必须收口到 `scripts/lib/` 的东西：

- 什么算产品源码（目录白名单/扩展名）
- 范围键怎么归（模块 → 键的映射）
- 谁算豁免（注释标记/白名单）
- 失败行长什么样（诊断行正则）
- 版本号从哪读
- 默认值是多少

检验方法：`grep` 同一段正则或同一个字面量，全仓应只有 1 处定义。

**两份的错位方向通常是互相掩护**：A 认为"没触及"→ 不要求；B 认为"触及了"→ 也没人看。两边都松，用户看到全绿。

## 五、失败输出必须可归因

聚合几十上百个门禁时，最常见的坏输出是：

```
❌ 静态护栏聚合失败
```

人无法定位 → 开始忽略红灯 → 门禁社会性死亡。

失败行抽取必须同时覆盖「红项」和「红项的原因行」：

```js
function failureLines(out) {
  const RE = /(❌|✗|FAIL|失败|Error:|error TS|AssertionError|^\s*↳|!\s*S\d+\s|⚠.*跳过)/;
  return [...new Set(out.split('\n').filter((l) => RE.test(l)).map((l) => l.trim()))];
}
```

注意 `^\s*↳`（原因行）、`! S15`（自证失败标记）、`⚠ 跳过`——三者最常被漏，漏掉就等于"红了但不知道为什么"。

**这段正则只能有一份**，放 `scripts/lib/gate-runner.mjs`，聚合器与本地调试副本都 import。

## 六、EXIT 码与四态

| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 全部通过 | 继续 |
| 1 | 判据红（产品/规范） | 修 |
| 2 | 配置/参数错误 | 修调用方式 |
| 3 | SUSPECT：全量红但单跑绿 | 疑似设施，先归因 |

**"跳过"不许计入通过数。** 报告写"21/21 通过"而其中 3 个是跳过的，等于谎报。跳过必须单独可见。

## 七、成本控制

门禁跑 20 分钟，人就不跑了；不跑的门禁等于不存在。

- 单条门禁目标 < 5s，超 30s 的必须有 `timeoutMs` 并显式处理超时
- 全量入口设**熔断**：同一失败签名连败 2 次，锁全量入口，要求先做三项归因（时间线 / 环境 diff / 数据状态）再解锁
- 失败后先**单跑复核**，用几秒的成本区分"设施噪声"和"产品缺陷"
- 长任务必须落日志，末尾输出**独立一行的哨兵**（如 `EXIT=0`）；没有哨兵 = 进程被杀 = 结论作废

## 八、注册（否则是死代码）

新守卫必须两处登记：

1. 聚合器（`check-all.mjs` / `check-guards.mjs`）的步骤表
2. 注册守卫（检查"每个 check 脚本都被注册了"）

注册守卫本身也要有判据：`scripts` 目录里的 `check-*.mjs` 数量 vs 聚合器注册数量，差值 > 0 → 判红并点名未注册的脚本。
