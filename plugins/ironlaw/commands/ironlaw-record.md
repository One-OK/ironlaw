**必须**加载 `ironlaw-record` 技能。

产出两件东西：

1. **七段变更档案**（模板：`assets/change-record-template.md`）
   - §1 根因 / §2 影响链（六类枚举）/ §2.5 **机器可执行断言表** / §2.6 未覆盖键与理由
   - §3 未修点与理由 / §4 用户可见影响与恢复路径 / §5 回滚方案 / §6 验证证据 / §7 完成判据（含负控制）
2. **三段式提交信息**（模板：`assets/commit-msg-template.txt`）
   - 行首固定 `根因:` / `影响链:` / `验证:`

**§2.5 断言表的硬要求**：

- 每条断言必须机器可执行：`检索式` 是 JS 正则，`范围` 是真实存在的路径，`期望` 是 `>=N` 或 `=N`。
- 机器算出的每个触及范围键，必须被至少一条断言覆盖，或在 §2.6 给 ≥8 字理由。
- 一条断言都没有的档案，等于没写档案。

写完**必须**执行：

```bash
node <skill>/scripts/verify-record.mjs docs/change-records/<file>.md
```

输出 `OK` 才算完成。任何一条断言不成立，回去改代码或改断言——**不许放宽断言让它变绿**。
