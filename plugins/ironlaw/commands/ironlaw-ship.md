**必须**加载 `ironlaw-ship` 技能。

按七步顺序铁律执行，**顺序不能换**：

```
① bump 版本（三处一致）
② commit（三段式）
③ push（三条判据全部核对）
④ 出包 / 上传
⑤ 部署
⑥ 线上真值核验（不看脚本自称成功，只看接口返回）
⑦ 台账登记 + 再推送
```

**三条最容易出错的地方，每次都要显式确认**：

1. **push 成功三判据** —— 单独捕获 `$?`（禁止管道）+ reflog + 远端 `ls-remote`。三者一致才算推上去了。
2. **「push 成功」≠「部署了」** —— 线上真值只认实际接口返回的版本号，不认部署脚本的 exit code。
3. **台账是手抄件，必须跟机读源一致** —— 版本号、基线提交前缀长度、入口文件名，任何一处脱节都会让下次部署被拦。

收尾**必须**跑：

```bash
node <skill>/scripts/ship-truth.mjs --config ship.json
```

四个真值源（本地 / 远端 / 线上 / 分发）全部一致才能宣布发版完成。

任何一步失败，**先说清是哪一步、根因是什么**，不要用「重试一次」掩盖。
